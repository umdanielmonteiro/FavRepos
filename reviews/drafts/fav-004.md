## Why it matters

REA is a command-line and MCP toolkit for evidence-oriented analysis of software artifacts and runtime behavior. Its documented targets include native binaries, JavaScript/Electron apps, .NET assemblies, Android packages/devices, firmware, websites, saved network captures, SQLite snapshots, and other formats. It may fit software development, interoperability, software preservation, and authorized security research. These use cases do not authorize analysis of third-party systems or bypassing licenses.

## Requirements and integration

The v6.7.0 [installation guide](https://github.com/morluto/rea/blob/27dc42d/docs/installation.md) requires Node.js 22.19+, 24.11+, or 26+, and npm for setup/CLI. Some static JavaScript and .NET work does not require a native analysis engine. Other targets need caller-provided tools such as Ghidra, Hopper, IDA, JADX/JDK, ADB, Binwalk/Unblob, a browser, tshark, or format-specific utilities. Exact requirements vary by target and host; Linux process ownership checks may require a procps-compatible `ps`. Provider and commercial-tool costs are separate from REA.

Codex compatibility is directly documented: `npx rea-agents setup` can register a local MCP server and install matching instructions. This is an optional configuration-changing setup flow; no integration was activated for this review. Terminal use is also documented. REA is not merely a prompt or skill: it is a CLI/MCP tool with agent workflow instructions.

No per-call API/token cost is stated for REA itself. Model-provider calls made by Codex may have separate account costs and data policies. The project describes analyses as local, but results are sent to the connected agent/model; users should assess that model provider's data policy.

## Security, privacy, and license

The toolkit can inspect files, invoke caller-supplied analysis providers, capture processes, interact with Android devices, and inspect browser/network evidence. Runtime workflows can have effects under the user's permissions; scope and target authorization matter. Installing MCP configuration and instructions changes agent configuration, and should be reviewed before approval. Static analysis and runtime capture have different exposure and execution characteristics.

REA-authored code is MIT. Third-party code and tools keep their own licenses; the README specifically calls out commercial decompilers and prohibits unauthorized access/license circumvention. Maintenance appears active from the release cadence, but this is not a security assurance. No independent vulnerability audit was conducted.
