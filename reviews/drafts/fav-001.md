## Why it matters

Whisper is OpenAI's open-weight, Python-based automatic speech recognition (ASR) project. Its documented tasks are transcription in the spoken language, translation of speech into English, and language identification. The repository provides model weights, a command-line program, and a Python library. It is a plausible component for caption drafting, searchable media archives, interview and lecture transcription, and multilingual research workflows, provided outputs are checked by people for the intended domain. These are **inferred use cases**, not sector-specific validation or a production recommendation. [R1][R3]

The canonical URL resolves to the `openai/whisper` repository. The publisher is OpenAI, the source platform is GitHub, and the resource type is **Python library plus downloadable model weights**, not an organization, hosted API, Codex skill, or MCP server. The publisher-supplied description from the original catalog entry is omitted from this candidate; the catalog uses a separate FavRepos-authored summary. No duplicate canonical URL was identified during the original review of the 49-record inventory, which is a historical baseline. [R1][R4]

## Architecture and technologies

The upstream describes a multitask encoder-decoder Transformer trained with task tokens. The Python implementation uses PyTorch tensors and modules, a tokenizer based on `tiktoken`, and log-Mel spectrogram preprocessing. The file loader invokes the local `ffmpeg` CLI to decode and resample audio to mono 16 kHz. The transcribe path reads a complete input file and processes it using a 30-second sliding window. This implies that long recordings can create substantial host RAM pressure even if inference is windowed; no memory measurement was made here. The upstream's claims of robustness and model speed remain developer claims. [R1][R4][R6][R7][R8]

Six size classes (`tiny`, `base`, `small`, `medium`, `large`, `turbo`) are documented, with English-only variants for the first four. The upstream estimates GPU VRAM at roughly 1, 1, 2, 5, 10 and 6 GB respectively. These are approximate **developer estimates**, not admission criteria for all devices. Its relative speeds were measured by upstream on an A100 with English speech and should not be generalized to a user's hardware. The model card and README disagree slightly about turbo parameter count; this review does not resolve that inconsistency. [R1][R3]

## Requirements and integration

**Operating systems.** The README documents `ffmpeg` installation routes for Ubuntu/Debian, Arch Linux, macOS and Windows. That establishes documented installation routes, not successful tests on every OS. The package manifest declares Python `>=3.8` and classifiers through 3.13, while the README says its authors trained/tested with Python 3.9.9 and PyTorch 1.10.1 and expected compatibility with Python 3.8–3.11. Treat the broader manifest range as package metadata rather than proof of end-to-end compatibility. A Rust toolchain may be needed where `tiktoken` has no prebuilt wheel. [R1][R4]

**Hardware.** CPU execution is available in the CLI source; GPU use depends on a working PyTorch accelerator stack and sufficient VRAM. No universal CPU RAM minimum, latency, energy use, or real-time capability was established. Model downloads, installation disk usage, and data retention must be budgeted separately. [R1][R9]

**Installation and invocation (documented; not executed).** Upstream documents `pip install -U openai-whisper` or installation directly from GitHub, plus an independently installed `ffmpeg` executable. The package declares a `whisper` console script. Examples use `whisper audio.mp3 --model turbo`, or Python's `whisper.load_model(...); model.transcribe(...)`. Lower-level language detection and decoding calls are documented. The CLI source at the reviewed release exposes TXT, VTT, SRT, TSV and JSON output formats; word timestamps are labeled experimental. [R1][R4][R9]

**Codex and automation.** No native Codex skill, MCP server or Codex-specific integration is documented in the inspected upstream sources. Codex could *possibly* orchestrate the CLI or a Python wrapper in an explicitly authorized, isolated environment; this is an integration inference, **not verified Codex compatibility** and not a reason to populate the catalog's `codex_compatibility` field. A separate service or MCP adapter could expose transcription to other tools, but that adapter is outside this repository. The local package is distinct from any hosted OpenAI speech API: installing it does not itself provision an API endpoint or require an OpenAI API key. Normal package/model acquisition still requires a download unless assets have been obtained in advance. No account, API cost or service-level guarantee for the local library was found in the reviewed sources. [R1][R4][R8][R9]

## Security, privacy, and license

The inspected code path launches local `ffmpeg` and uses locally loaded PyTorch model weights for inference; the implementation also includes a downloader for published weights. **Inference can therefore be deployed locally**, but this static inspection does not prove that every dependency or wrapper is offline, or that a particular workflow prevents uploads, logs, telemetry or retention. Treat audio, transcripts and filenames as potentially sensitive; review consent, access controls, storage, deletion, model acquisition and the surrounding application's data flow before operational use. The reviewed release passes `weights_only=True` to `torch.load` when PyTorch is at least 1.13; older PyTorch versions follow another path. Do not load arbitrary model files or process untrusted media without an appropriate isolation and update policy. [R6][R8][R10]

The repository's MIT license permits commercial use, modification and distribution of the licensed software, provided the copyright and permission notice is retained. The upstream README explicitly states that both code and weights are MIT licensed. This does not grant rights to source recordings, transcripts, training data, bundled third-party dependencies, or trademarks. Verify those separately for a commercial deployment. This is a license reading, not legal advice. [R1][R5]

The model card warns about transcription without consent, surveillance uses, subjective classification and consequential decisions. It reports possible hallucinations, repetitive output and uneven performance across languages and groups. Human review and domain-specific evaluation are necessary before a transcription influences a sensitive decision. [R3]

## Limitations and maintenance

Known upstream limitations include hallucinated text, repetition, language and accent disparities, full-file loading, and lack of out-of-the-box real-time transcription. `turbo` is unsuitable for speech translation to English as documented. Experimental word timestamps should be checked against the audio before publishing subtitles. The sources do not establish speaker diarization, speaker identification, guaranteed word-level alignment, live streaming, or certified suitability for legal/medical decisions. [R1][R3][R9]

The published release list shows `v20250625` as the latest release visible at the review date; its changelog lists dependency, correctness and security-related changes. That demonstrates historical maintenance, not a guaranteed update cadence, support SLA, or response time for future vulnerabilities. [R2][R10]
