## Why it matters

This resource is the official documentation for Remotion, a React-based framework for creating videos programmatically. It documents compositions, a Studio preview, CLI and Node.js rendering APIs, a Player, and optional deployment/integration packages. It is documentation for a framework ecosystem, not a separate software repository or a single hosted video service. [R1][R2]

Remotion's core workflow combines React code with frame/time-based visuals and rendering. The renderer provides APIs such as `renderMedia()`, `renderFrames()` and `renderStill()`; the CLI and optional cloud adapters are separate components. Lambda, Vercel and Cloud Run rendering, the Player, AI plugins and other add-ons should not be mistaken for inherent services supplied by the documentation or framework core. [R2]

## Architecture and requirements

**Framework model.** Developers create React compositions and render them through Remotion packages. The local Studio provides preview and development tooling; `@remotion/renderer` exposes Node.js APIs for server-side rendering and the CLI. External rendering adapters such as Lambda/Vercel/Cloud Run add separate infrastructure, credentials, deployment and provider costs. [R1][R2]

**Runtime and OS.** The current getting-started docs specify Node.js 16 or Bun 1.0.3 as the minimum runtime; recommend package managers including npm, Bun, pnpm and Yarn; require macOS 15 or later and Linux libc 2.35 or later, with additional Linux packages; and list Alpine Linux and NixOS as unsupported. The exact package version and rendering mode can impose additional requirements. The documentation does not state a universal hardware or GPU minimum; practical render time and memory depend on composition, frame size, codecs and concurrency. [R1]

**Rendering and dependencies.** The server renderer uses browser rendering and FFmpeg-related tooling documented by its API references; the renderer API can ensure a browser and FFmpeg/ffprobe are available. Media formats, codec support, fonts and third-party assets should be checked independently. Hardware acceleration is not a blanket guarantee. [R2]

**Codex.** Remotion's docs explicitly mention Codex as a coding agent and link agent skills and a Codex plugin. That indicates documented workflow integration for authoring code. It does not turn the framework documentation into a Codex plugin, MCP server or hosted generation tool; those are separate catalog resources/integrations. [R6][R7]

## Costs and licensing

The docs describe a proprietary Remotion License. The publisher's current FAQ says individuals, organizations with up to three people and certain other groups are eligible for a free license; for companies outside those exemptions, “Remotion for Creators” is priced per seat and “Remotion for Automators” by render, with a minimum monthly spend stated by the publisher. These terms, eligibility rules and prices can change and should be checked against the current official terms before commercial deployment. [R5]

The FAQ defines automation around programmatic render APIs/commands and the Player, and gives restrictions on offering arbitrary customer code for rendering. This is a material business-model and architecture consideration. Remotion's license does not include rights to third-party codec patents such as H.264/AVC, HEVC or AAC, nor does it cover every bundled dependency or asset. [R5]

## Security, privacy, and license

The framework is documented as self-hosted; the developer controls project hosting and render infrastructure. Data may still leave the local environment through external media/fonts, third-party APIs, cloud rendering adapters, browser fetches or license telemetry, depending on project configuration. Current docs describe usage telemetry for some license/render paths, with different rules across versions and products. Review the precise renderer package, license mode, assets, network requests and hosting path for the chosen deployment. No security audit or privacy certification was established here. [R4][R5]

Because Remotion's license is proprietary/source-available and usage conditions vary by organization and product model, read the current Terms and Conditions. Also confirm rights for fonts, music, imagery, footage, codecs and other assets. The licensing pages are vendor-authored guidance, not legal advice. [R4][R5]

## Limitations and maintenance

Remotion requires React/JavaScript development and its rendering stack; it is not a general-purpose GUI video editor. Rendering can be resource-intensive, and timing, browser compatibility, codec availability, assets and package-version alignment affect results. The docs warn that Remotion packages should use matching exact versions. Some OS environments are explicitly unsupported. Service features like Lambda and the Editor Starter have independent setup, pricing and terms. [R1][R2][R5]

The docs are living pages, and this snapshot records the date and framework release rather than pretending the whole documentation site has a versioned SHA. Recheck runtime support, license terms, package compatibility and prices before implementation.
