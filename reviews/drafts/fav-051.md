## Why it matters

Boop is a native macOS developer utility for transforming text in a scratchpad with bundled or custom scripts. It fits developer productivity and text-processing workflows. Its user interface and script model make it a desktop application, not an agent skill, Codex plugin, or MCP server.

The UI documentation describes opening/pasting text, choosing a script from a searchable picker, and copying transformed text. Scripts may access or update the editor's full text and selection through the bridge. A custom script directory can be configured. Community scripts therefore warrant source review before use. The docs say scripts load at app launch and run in persistent JavaScriptCore virtual machines.

The source repository contains Swift and JavaScript components according to GitHub's repository pages, but this review did not perform a full architecture or dependency audit. The scripting docs describe no browser `window`, Node `process`, or `Crypto` globals and no direct includes/requires. The documentation's word “sandboxed” does not establish isolation from all local data, clipboard interactions, network access, or OS resources across every distributed build. No claim about application network permissions or signed-build entitlements is made.

## Requirements and integration

- **Platform:** macOS is the documented target. A minimum supported macOS version was not established from the inspected documentation.
- **Distribution:** GitHub releases and Mac App Store. Homebrew is described as unofficial. The release page's latest listed version is 1.4.0. Distribution builds may include signing/sandbox settings that differ from a locally built development app; those differences were not examined.
- **Build/development:** Xcode is required for compiling from source. The README points to `Boop/Boop.xcodeproj`; script authors can work with the app without compiling the app.
- **Scripts:** JavaScript on JavaScriptCore, with Boop's custom `ScriptExecution` API. This is not Node.js and lacks several browser/Node globals.
- **Codex:** No Codex-specific integration was documented in the consulted sources. Codex could not be considered integrated merely because Boop is useful to developers; compatibility is unknown.
- **Network, cost, accounts:** No account or paid API requirement was found in the consulted documents. Network behavior was not audited; absence of a documented network requirement is not proof that no network access occurs.

## Security, privacy, and license

Text placed in a scratchpad can be sensitive. The documentation describes script access through the execution object, including editor text and selection, but this review did not inspect every shipped script or test app-level access controls. Custom or community scripts should be treated as executable code even where JavaScriptCore limits their APIs. Do not assume they are safe or completely isolated.

MIT is declared for the repository. The documentation specifically recommends checking individual script and module licenses and attributing third-party code. A repository-wide license does not automatically grant rights to every dependency or user-contributed snippet. No security certification is claimed.

## Requirements, risks, and unknowns

- Exact minimum macOS/Xcode versions and differences between distribution builds were not verified in the documentary review. The owner reported checks on the tested distribution, but the reviewer did not inspect the binary or verify its signing configuration.
- The scripting API deliberately exposes selected document state; clipboard and file interactions outside that bridge were not tested.
- No network traffic was analyzed; network behavior remains unknown.
- Community scripts can transform or expose text available to their API. Review their source and provenance.
- Release cadence appears sparse in the pages reviewed; current maintenance status is uncertain.
