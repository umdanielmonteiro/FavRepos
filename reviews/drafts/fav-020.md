## Architecture and capabilities

The current README describes a single desktop application using Tauri with a Rust backend and Next.js frontend. It documents audio capture, real-time transcription and local transcript/model storage. Whisper or Parakeet models are used for transcription according to the README. Summary generation can use a local Ollama instance or selected external providers, including Claude, Groq, OpenRouter and an OpenAI-compatible endpoint. This creates distinct data paths: local audio transcription may remain on-device, while summary text sent to a remote provider leaves the device. The project's broader “100% local” wording should not be applied to configurations using cloud summary providers. [R1]

The README documents importing audio as beta, model downloads, microphone/system-audio capture, and GPU options that vary by package/build. The v0.4.1 release notes describe reliability changes to microphones, transcript coverage, summary handling and model downloads. These are claims about a release, not independently verified behavior. [R1][R2]

Speaker diarization/identification is described in the README's PRO section as planned/coming soon rather than a confirmed Community Edition capability. It should not be inferred from the former publisher-supplied catalog description, which is omitted from this candidate pending republication provenance review. [R1]

## Requirements and integration

**Platforms and hardware.** The README documents Windows x64 with AVX2 CPU support, an Apple Silicon macOS installer, and Linux source builds. Windows packages are described as using a Vulkan-enabled Whisper build; macOS packaging as using Metal/CoreML; Linux acceleration depends on build configuration. CUDA requires an appropriately configured source build. This is not a universal GPU or minimum-memory specification. No requirements for RAM, disk, meeting duration or real-time throughput were established. [R1]

**Installation and dependencies.** Windows and macOS binary installation paths are documented; Linux uses source build guides, with a quick-start path naming `pnpm` and a build script. Developer setup requires Rust and Node.js. These commands were read only and not run. Model weights must be downloaded or otherwise supplied; exact storage footprint is model dependent. [R1]

**Audio and permissions.** Capturing system audio and microphone audio requires operating-system-level device access and, where applicable, user permissions. The README specifically documents native macOS permission dialogs and microphone/system-audio mixing. Available capture paths can differ by OS and device. No live meeting client integration matrix or device compatibility test was conducted. [R1]

**Providers and costs.** Local summarization through Ollama requires a separately installed local model runtime and sufficient host resources. Remote providers require accounts, API credentials and provider charges/terms; the README mentions Claude, Groq, OpenRouter and OpenAI-compatible endpoints. The release repository does not establish a universal price or guarantee that every meeting content path stays local. [R1]

**Codex.** No native Codex skill, plugin, MCP server or Codex integration was found in the reviewed first-party documentation. Any external orchestration would be a separate, untested possibility and is not cataloged as compatibility.

## Security, privacy, and license

Audio recordings, transcripts, meeting titles, participant names and summaries can contain sensitive or confidential information. If a remote LLM is selected, summary requests may disclose transcript content to that provider; users must review its terms, retention and account controls. The project claims recordings and transcripts are stored locally and usage analytics are optional/off by default, but its privacy policy contains a placeholder update date and states it applies to v0.0.5 and later. The current README identifies v0.4.1 and lists multiple remote summary providers, so those documents should be checked against current source and actual defaults before relying on the privacy claims. [R1][R3]

Meeting recording also raises participant-consent and organizational-policy questions. Permission to capture microphone/system audio is a technical gate, not consent from participants. Human review is needed for transcripts and generated notes; no accuracy or diarization benchmark was performed. [R1]

The repository declares MIT for the application. The models (Whisper, Parakeet and conversions), borrowed code and other dependencies have separate license and attribution terms. The README names borrowed code from whisper.cpp, Screenpipe and transcribe-rs and credits NVIDIA and a model converter. Verify exact versions and model terms for a distribution or commercial deployment. This is not legal advice. [R1]
