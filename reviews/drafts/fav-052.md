## Why it matters

The README groups skills into Engineering and Productivity and distinguishes user-invoked skills from model-invoked ones. This classification differs from broad skills catalogs by focusing on engineering practices, repository setup, code changes, issue workflow, and related development tasks. ## Requirements and integration

- **Codex:** Current README documents `codex plugin marketplace add mattpocock/skills` followed by `codex plugin add mattpocock-skills@mattpocock`. Repository file listing includes `.agents/`; release history has referred to per-skill Codex metadata. This confirms documentation, not effective installation or runtime compatibility. No MCP server is documented.
- **Claude Code:** README documents installation as a Claude Code plugin, with a managed bundle and automatic updates.
- **skills.sh:** README documents selectable skills and agent targets, copied as editable files; updates are manual. It warns against installing both editable and plugin copies for the same agent because skills may duplicate.
- **Other hosts:** README documents GitHub Copilot, Gemini CLI, and generic Skills CLI installations for hosts such as Cursor, OpenCode, Devin, Windsurf, Amp, and Pi. Support depends on each host's implementation.
- **Setup effects:** `/setup-matt-pocock-skills` is documented to ask about issue trackers, triage labels, and documentation locations. Other skills may write specs/tickets, edit files, run tests, or use configured tools. Review each skill's instructions and the host's permissions before invocation.
- **Runtime:** No single runtime requirement applies to all Markdown skills. The repository includes scripts/package metadata; this review did not enumerate dependencies or execute setup scripts.

The README and release history have changed over time: an earlier release note described a native Codex plugin as deferred, while the current README documents Codex marketplace/add commands. This review follows the current page at retrieval and records the version drift; it does not claim successful plugin operation.

## Security, privacy, and license

Skills are instructions loaded into an agent and may influence how the agent reads a repository, edits files, invokes tools, or interacts with configured services. Treat third-party skill content as untrusted, inspect SKILL.md and referenced files, and use host permissions/approval controls. Prompt injection can be introduced through project content read by an agent; no skill bundle is itself a security boundary.

MIT is declared at repository level. Check individual dependencies, copied material, generated files, and third-party skills for their own notices. The collection can affect engineering processes by prescribing interview, implementation, testing, issue creation, or commit workflows; these steps should remain subject to the user's authorization and local repository policy. No security assessment or quality outcome is claimed.

## Requirements, risks, and unknowns

- Exact skill-file count outside the public README list was not established; “27” means README catalog entries only.
- Runtime prerequisites and side effects differ by skill and were not exhaustively inventoried.
- Some instructions can result in repository writes, external issue creation, command execution, or delegation when invoked; scope and permissions must be reviewed per skill.
- Plugin behavior and update semantics were documented but not tested. Editable copies can diverge from upstream.
- The collection overlaps functionally with ECC and other agent-skill collections already cataloged, but focuses on composable engineering workflow instructions. No comparative efficacy study was made.
- Codex marketplace commands are present in the current README, while older release text reported Codex plugin support as deferred; current support remains documentary pending installation and validation.
