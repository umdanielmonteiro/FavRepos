## Requirements and integration

Documented base requirements are Node.js 22.18+, Python 3.10+, FFmpeg, Chrome, and either Claude Code or Codex CLI logged in. The project installs Python dependencies and builds its web app; video and image workflows may require substantial time/storage and agent/model usage. Optional Yating, Pixabay, Freesound and posting API credentials are described. The application can use up to six builders per video and a global agent cap of twelve; increasing parallelism may increase provider usage, although exact billing is not stated.

Codex compatibility is explicit at the CLI/workflow layer: the application expects Codex CLI, reads the repository's `AGENTS.md`, and delegates work through that account. This is not a Codex MCP server or native desktop plugin. The README states `CODEX_SANDBOX` defaults to `danger-full-access` and that `workspace-write` blocks the Chrome renderer; this is a material security and compatibility setting that needs review before use. No setup or generation was performed.

## Security, privacy, and license

The application processes user-provided reference media locally according to the README, but delegated agent/model calls use the user's Claude Code or Codex account and its provider policies. Media sources and generated assets may be uploaded to model or optional provider APIs. Credentials are stored in a user-level secrets file outside the repository; protect its permissions and never commit it. Optional posting credentials can publish externally, so posting behavior requires explicit human review.

The default `danger-full-access` Codex sandbox setting can grant the renderer broad local access depending on host behavior; the README says a more restrictive workspace-write mode blocks part of the app. This creates a significant privilege tradeoff. Browser/Chrome automation and shell access also warrant careful review. The README's stated Windows-heavy testing means macOS/Linux behavior is less established. MIT applies to project code only; third-party assets, skills, reference footage, music, voices, and model outputs remain subject to their respective licenses and rights.
