## 1. Prioritization method

Priority is a planning queue only. It is not an editorial verdict, quality rating, safety judgment, or compatibility claim. P1 means a comparatively bounded, useful pilot with a plausible synthetic test; P2 means a useful but more dependent or costly evaluation; P3 means defer pending material, access, hardware, rights, or scope decisions; N/A means the entry is primarily documentation, an organization, a directory, or otherwise not meaningfully evaluated by executing the catalogued item. Complexity estimates cover a responsibly scoped pilot, not full deployment.

Resource names, types, categories, and known execution requirements are taken from the canonical catalog. Risk, synthetic-data feasibility, evaluation mode, priority, and complexity are planning inferences, not observations. “Unknown” is intentional where the catalog and corresponding draft do not establish a requirement. A documented requirement is not a verified one.

## 3. First wave: reprioritized proposal

The requested initial order is adjusted based on `reviews/drafts/fav-050.md` through `fav-053.md` and `fav-039.md`, all documentary/source reviews that report no practical test.

1. **fav-050 Humanizer (P1, first):** markdown skill with a synthetic prose input; no application install is required if an authorized host can load a reviewed copy. Host model, retention, and exact skill revision remain prerequisites.
2. **fav-051 Boop (P1):** a focused macOS text transformation with a synthetic input. JavaScriptCore executes custom transformations, so review the selected script and restrict file access. Distribution choice (release/App Store/source) must be decided.
3. **fav-053 Diagram Design (P1):** generate one simple diagram from synthetic requirements. First pilot should use system fonts and inspect HTML/SVG; PNG export is optional and requires separate approval for Playwright/Chromium installation. The upstream type-count discrepancy remains unresolved.
4. **fav-052 Skills for Real Engineers (P2):** move after narrower skills because the repository contains multiple skills with varying shell, file, or issue-tracker actions. Select one skill only after static review; keep integrations unavailable.
5. **fav-039 HyperFrames (P2):** move to the end because rendering executes HTML/JavaScript in a headless browser and reads media paths. It needs a disposable no-network environment, Node.js 22+, FFmpeg, and a confirmed immutable upstream revision. Avoid hosted rendering.

This ordering is an execution-planning recommendation only. It does not change `editorial_verdict`, `personal_impressions`, or `hands_on_tested`.

## 4. Pilot protocols (proposed; not executed)

### 4.1 fav-050 Humanizer

- **Hypothesis:** the selected skill can revise synthetic prose while preserving its stated meaning and producing an observable, reviewable text diff.
- **Functions under evaluation:** instruction loading, transformation behavior, preservation of facts/intent, and whether the workflow requests external tools or data.
- **Scope/exclusions:** one skill and one synthetic input/output; exclude private prose, publication claims, quality generalization, automatic installation, and external integrations.
- **Minimum environment:** disposable agent profile/workspace, reviewed skill files, and a host whose model/provider and retention behavior have been documented. Exact runtime is host-dependent and unknown.
- **Version/commit:** resolve and record a full immutable upstream commit before execution; the draft documents install paths but does not pin a commit. Do not substitute a branch name or invented SHA.
- **Synthetic input:** a generated 100–150 word neutral paragraph with deliberately repeated phrasing and several fixed facts, plus explicit “do not change” facts.
- **Proposed procedure:** inspect skill instructions and any scripts; configure a fresh workspace with no private mounts or connected services; load the pinned skill using an owner-approved method; submit the fixture; save input, output, diff, host/model metadata and transcript with secrets removed; compare fixed facts and capture deviations. No commands are specified because no exact operational command was confirmed.
- **Expected observable results:** output text, diff, whether facts remain intact, prompt/tool calls visible to evaluator, and any network or permission requests.
- **Pass/fail/block:** pass if requested style transformation is observable and fixed facts remain; fail if it silently changes fixed facts, reads outside fixture scope, or invokes unapproved tools; block if the host's data handling, revision, or isolation cannot be established.
- **Evidence/logs:** resource ID, evaluator, date, host/model/version, upstream commit, sanitized prompt/input/output/diff, tool activity and errors; no private text.
- **Safety/privacy:** synthetic text only; no personal or client writing; no production/personal tokens; deny file/network/tool access beyond the isolated fixture.
- **Dependencies/costs/permissions:** model/provider may be paid or retain prompts; confirm pricing, account, and data terms before enabling. Owner approval required for the exact pilot.
- **Cleanup/reversal:** delete disposable profile and fixture/output after evidence review if retention policy permits; remove copied skill folder; no global install.
- **Owner decisions:** approve host/provider; choose exact pinned revision; decide retention/evidence retention; confirm evaluation criteria for “meaning preserved.”

### 4.2 fav-051 Boop

- **Hypothesis:** Boop can apply a selected, reviewed text transformation to a synthetic snippet and expose the result without needing unrelated data or service access.
- **Functions under evaluation:** text scratchpad, transformation discovery/selection, JavaScriptCore script execution, undo/copy/export behavior if documented for the pinned release.
- **Scope/exclusions:** macOS only; one transformation and synthetic text. No Homebrew (catalog calls it unofficial), no external scripts not reviewed, no clipboard containing real data, no network behavior assumed.
- **Minimum environment:** isolated macOS user/profile or disposable VM, chosen official distribution, and OS/Xcode requirements confirmed from pinned release. Current catalog does not establish minimum macOS/Xcode version.
- **Version/commit:** select a release or source commit and record its immutable identity before execution; do not assume latest. Distribution must be chosen and provenance checked.
- **Synthetic input:** fixed text such as `alpha beta 123`, with expected transformation specified before the run (for example, normalize whitespace); use only a reviewed built-in or owner-reviewed script.
- **Proposed procedure:** inspect source/release signature and script contents; install only after Gate 2; launch in isolated account; enter fixture; apply the selected transformation; compare output with prewritten expectation; inspect filesystem/network permissions and logs. No command is provided because none was confirmed by the documentary materials.
- **Expected observable results:** application version, transformation selected, input/output, behavior on empty/Unicode text if in scope, undo behavior and any permission prompts.
- **Pass/fail/block:** pass if deterministic expected output and no out-of-scope access; fail for data loss, unexpected file/network access, or non-recoverable behavior; block if official distribution/revision, permissions, or required OS cannot be confirmed.
- **Evidence/logs:** screenshots only if permitted, sanitized fixture/output, OS/app version, upstream revision, permission prompts, errors; no clipboard or user documents.
- **Safety/privacy:** synthetic clipboard/text; deny contacts, documents, and network access unless separately approved; review every executable transformation.
- **Dependencies/costs/permissions:** macOS/Xcode or app distribution; App Store account/payment may apply. Owner authorizes exact installation route and script.
- **Cleanup/reversal:** remove app and disposable profile; restore clipboard; remove test script and fixture; retain only sanitized evidence.
- **Owner decisions:** distribution source, supported macOS baseline, transformation to test, acceptable permissions, and whether App Store costs are acceptable.

### 4.3 fav-053 Diagram Design

- **Functions under evaluation:** skill instructions, one HTML/inline-SVG diagram, labels/description fields, and optionally a local SVG export. PNG export is out of initial scope.

- **Minimum environment:** isolated agent workspace; reviewed skill and template files; local text/HTML inspection. If export is separately approved, use an isolated environment with confirmed Python requirement. Do not install Playwright/Chromium in this plan.
- **Version/commit:** resolve full commit before execution; current draft notes repository/source count mismatch (44/45) and mutable links, so identify exact commit and skill path first.
- **Synthetic input:** fictional “Northwind Demo” service map: browser → API → local test database, with no real domains, credentials, or data.
- **Proposed procedure:** inspect instructions/templates/scripts and default font configuration; choose system fonts; run only in a disposable host after approval; request a static diagram; save HTML/SVG; inspect markup before rendering; check labels, titles/descriptions, connectivity and any remote URLs. Optional SVG/PNG export requires its own permission and dependency review.
