## Why it matters

FreeLLMAPI is a self-hosted, single-user gateway that exposes a local OpenAI-compatible endpoint and routes requests to configured upstream providers. It also documents a dashboard, desktop app, CLI, MCP surface and Codex CLI launch recipe. It does not provide its own foundation-model inference or guarantee that provider free tiers remain available.

## Requirements and integration

- **Type:** self-hosted LLM API gateway/router with dashboard and optional desktop app/CLI/MCP endpoint. It does not host model weights or implement model inference itself.
- **Runtime:** README states Node.js 20+; installation options include Docker, Docker Compose, local Node/npm development and desktop builds for macOS/Windows. Hardware requirements are modest for the gateway itself, but provider inference runs remotely unless a custom local OpenAI-compatible endpoint is configured.
- **API:** local default `/v1` supports chat completions and documents routing strategies, streaming, tool calls, vision, embeddings and additional provider surfaces; consult the API guide for endpoint-specific compatibility rather than assuming full OpenAI API parity.
- **Credentials:** requires provider API keys (except any provider route explicitly documented as anonymous) and a unified gateway key. Security policy describes AES-256-GCM encrypted key storage, dashboard authentication on server deployments, and default loopback binding. Public network exposure is explicitly opt-in and not designed for multi-tenant use.
- **Codex:** README documents `launch-codex` for configuring a Codex CLI client to use the local base URL and gateway key, plus MCP endpoints for compatible clients. This does not establish support for ChatGPT subscription/Codex account credentials or every Codex product mode. Protocol compatibility and product authentication are separate.
- **Free tiers/cost:** provider quotas, models, billing and terms vary and may change; fallback does not remove provider limits. A signed model catalog is updated by the project; listed free access does not mean unlimited or production-grade. Project also documents optional premium service/catalog terms.
- **Data flow:** local gateway sends requests to selected upstream providers, with possible retries/fallback to other providers. Review routing, logging, cache and context-handoff settings before sending sensitive prompts.

## Security, privacy, and license

The router is a sensitive boundary because it holds provider credentials and forwards prompt content. The project documents encrypted-at-rest keys, a unified bearer token, dashboard authentication and loopback default binding. These are project claims, not an independent security audit. Exposing the service on a LAN/public interface increases risk; it is described as a single-user trusted-network tool with no multi-tenant auth. Logs, analytics, cache and optional context handoff may store or add request data. Data sent to upstream providers is governed by each provider's terms and retention policies; failover may send content to more than one provider.

The repository code is MIT licensed. This does not grant rights to upstream provider models or override provider terms, free-tier limits, acceptable-use rules or restrictions on proxying. The project says personal experimentation/learning, not production, and recommends paid APIs before shipping a real product. Do not use gateway routing to evade limits or provider policies. Do not send confidential or personal data without assessing each provider's data handling.
