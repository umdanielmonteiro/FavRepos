## Why it matters

VoiceStudio is an Electron desktop application with a local audio backend and a catalog of speech engines. The project documents workflows for voice cloning/design, dictation, transcription, video dubbing, stories and audiobook generation, plus a local API/MCP path and optional remote workers. The breadth of features is an upstream description; individual engine capabilities vary and were not exercised. [R1][R2]

The v0.5.6 release identifies the current shell as Electron; the README says v0.5.3 was the final Tauri release. The resource is an application, not one speech model. Its default OmniVoice engine and the many optional engines, checkpoints, tokenizers and voice presets have distinct requirements and licensing. [R1][R2]

## Architecture and model boundaries

The project presents an Electron UI with a Python backend and engine-specific environments. It exposes a local API, documents an MCP integration, and can use optional remote workers or external engine servers. The engine catalogue describes an OmniVoice-based default, other TTS engines and several ASR engines; some run on CPU, CUDA or Apple MPS, while others are restricted to Apple Silicon, need dedicated dependencies, or use an external API/server. This is a model orchestration application, not a single uniform inference implementation. [R2][R3]

Voice cloning depends on reference audio and the chosen engine. The guide recommends a clean 5–15 second recording; the application may accept longer clips but documents engine-specific truncation strategies. A saved voice or input clip does not guarantee identical behavior across engines. The README's “646 languages” phrase is an upstream product claim and should not be read as independently established equal-quality support for every feature or engine. [R2][R3]

## Requirements and integration

**Operating systems.** v0.5.6 release assets are listed for Windows x64, macOS Apple Silicon and Intel, and Linux x64. The engine docs add caveats for individual runtimes; some engines exclude Windows or Intel Mac. Docker is documented as a headless backend and is not the desktop application. These are upstream target claims, not install tests. [R1][R3]

**Runtime and hardware.** The desktop application is Electron-based; building from source requires Bun and setup of its Python API backend, with Rust/tooling among development prerequisites. Model needs vary: the engine guide documents CPU, CUDA and MPS for the default OmniVoice, and other engine-specific combinations. GPU requirements, VRAM, disk footprint and latency depend on the selected model; no single minimum applies. The project asks agent-driven installers to inspect OS, CPU/GPU, RAM/VRAM and free disk, verify the actual compute device, and ask before downloading models. [R3][R5]

**APIs, MCP and Codex.** The project documents a local API and MCP integration, and its v0.5.6 release says connection setup is available for Codex CLI. It also documents a Codex-aware installation skill. This is more specific than generic ability to invoke commands: it is project-provided setup guidance and integration, but remains untested in this review. It does not establish compatibility with every Codex host or desktop configuration. [R1][R5]

**Costs.** The application is described as free/local, but compute, storage and model downloads consume local resources. Optional remote workers or external providers may add costs and data movement. Review provider terms and usage costs for each configured engine; no single cost estimate covers the catalog. [R2][R3]

## Security, privacy, and license

Local processing is a documented mode, and the README says analytics requires consent and remote services are optional. These statements do not prove every engine is local or every configuration remains offline. A local API/MCP surface, Docker deployment and remote workers create distinct trust boundaries. Voice samples and derived voice profiles are sensitive biometric-like data: restrict access, storage, backups and retention, and obtain permission before cloning any person's voice. The developer explicitly tells agents to ask before model downloads, keep cloud/analytics opt-in and verify compute hardware. [R2][R5]

The application uses AGPL-3.0. That license does not automatically govern every engine, model weight, tokenizer, preset voice, input recording or output. VoiceStudio's model catalogue includes license evidence and instructs users to review exact model terms; some models may be gated until their license is accepted. Commercial use must be checked engine by engine. Clone voices only with consent. [R1][R4]

## Limitations and maintenance

The tool's broad feature list masks engine-specific limitations, compute needs, language coverage, reference-audio limits and legal terms. The repository is actively changing; the v0.5.6 release is the pinned review point, and future main-branch behavior may differ. No external security audit, service guarantee or quality certification was established. [R1][R3]

Possible uses inferred from documented functionality include voice production, transcription, dubbing, audiobook creation, dictation and accessible media workflows.
