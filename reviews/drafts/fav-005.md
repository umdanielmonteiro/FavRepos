## Why it matters

Open Generative AI is a JavaScript/Next.js and Electron creative application for image, video, audio, lip-sync, clipping, and related generative workflows. The project describes hosted/API-backed and desktop local-inference options. Potential general sectors include creative production, marketing, and education; actual fit depends on provider terms, model licenses, hardware, and data handling.

## Requirements and integration

For source development, the README specifies Node.js 18+, npm, and cloning submodules. Desktop users can use release installers. Remote model generation requires a Muapi account/API key and network access; pricing and quotas are provider/model-specific and were not verified. Local inference needs disk space for engines and weights, and in the Wan2GP path a CUDA/ROCm GPU and Python/PyTorch installation. The project documents multi-GB model assets and local storage paths. macOS releases are described as not notarized; Windows builds may trigger SmartScreen; Linux AppImage can encounter AppArmor/user-namespace restrictions.

Codex compatibility is not directly established for operating the application. A separate MCP/CLI studio appears among the app's tabs and a desktop local-engine path may connect to a user-hosted Wan2GP MCP server, but that is not evidence that the application itself is a Codex MCP server or plugin. Codex can inspect or modify source code as a general coding environment; that is not native product integration.

Potential costs include provider API calls, hosted account access, local hardware, storage, and electricity. The “free” claim should not be interpreted as free model inference. Token use is not central for image/video generation, but some agent/workflow features may use provider/model APIs and incur usage charges.

## Security, privacy, and license

The API flow sends prompts and may upload source images, audio, or video to Muapi-hosted URLs. Self-hosting the UI does not mean inference/media processing remains local. The desktop application stores the API key in local browser/Electron storage per the README architecture; local storage and machine access should be treated as sensitive. Local inference is a distinct mode, but the app may still make network requests for downloads and other features.

MIT covers the repository code, not commercial model weights, hosted APIs, generated outputs, or third-party components. For issue #309, the report remains open and no fix was confirmed in the examined release. For issue #310, a corrective change is declared in the later commit above, but its effectiveness and backport/release availability were not tested here. The v2.0.0 review target predates that commit. This assessment is not an independent vulnerability validation. Verify each model/API's rights, permitted outputs, retention policy, usage restrictions, and pricing before production use. The maintainers' no-filter claim also means users need their own content, consent, and abuse controls. No independent security audit was performed.

**Rationale:** Existing catalog verdict preserved. Functionality, deployment options, and API data flow are documented; claims about free/unrestricted access and model counts remain attributed and untested.
