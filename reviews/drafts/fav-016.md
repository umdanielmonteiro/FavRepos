## Why it matters

Prompts.chat combines a community prompt collection with a web application intended for browsing, sharing, saving and managing prompts. The repository also documents a CLI, self-hosting and AI-client integrations. Its README calls the project free/open source and claims self-hosting provides “complete privacy”; that privacy outcome is a maintainer claim and depends on deployment, telemetry, authentication, model providers and connected integrations. [R1][R2]

The site/application, source code, prompt text and community submissions are distinct content categories. The candidate LICENSE assigns MIT to source code/site-authored content and CC0 1.0 to prompt data, including user-submitted prompt text, with MIT as the default where file assignment is unclear. This exact file was confirmed at the candidate SHA. The declaration does not independently prove a contributor had rights to submit every item or resolve third-party assets. [R3]

## Architecture and product boundaries

This is more than a static prompt list: the repository documents a Next.js web application backed by PostgreSQL/Prisma, with authentication, user prompt management and integrations. The site, app, CLI and published prompt corpus have different deployment and trust boundaries. Authentication-provider secrets, database credentials, optional storage credentials and model-provider credentials must be supplied by the operator when corresponding features are enabled. Exact persistence and retention behavior should be verified against the chosen revision and deployment configuration. [R1][R4]

The MCP endpoint exposes prompt-related tools according to the project docs; the Claude Code plugin adds a host-specific package/configuration path. These are separate integration mechanisms. Community prompt entries are untrusted content: a prompt may contain instructions that attempt to override an agent’s policies, request secrets or cause consequential actions. Displaying, saving or passing such text to a model does not make its instructions trustworthy. [R5]

## Security, privacy, and license

Self-hosting may give an operator more control over storage, but it does not by itself prove that prompts, logs, analytics, backups, identity data or model requests stay private. Review the selected deployment's environment variables, telemetry, database access, OAuth configuration, logging and any external integrations. Do not place secrets, customer records or regulated information in community prompts or external model calls without appropriate controls and terms. [R1][R6]

Community prompts must be treated as data, not authoritative instructions. Prompt injection can be embedded in ordinary-looking content and may request disclosure or actions when passed into an agent. Apply review and least privilege to any workflow that consumes prompts. [R5]

The repository identifies MIT licensing for code/site-authored material and CC0 1.0 for prompt content/data. Check individual contributions, third-party assets and service terms where provenance is uncertain; repository-wide wording does not establish that every contributor had rights to submit every item. [R3]
