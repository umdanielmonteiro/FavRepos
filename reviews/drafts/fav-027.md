## Why it matters

Strix is an AI-assisted security testing CLI and agent runtime. It documents reconnaissance, active testing, exploit validation, reporting, and optional remediation workflows across code, web applications, and APIs. Application-security teams and authorized software testing are plausible professional contexts. Its testing can actively affect targets and must be confined to systems the operator owns or has explicit written authorization to assess.

## Requirements and integration

The README quick start lists Docker and an LLM provider key; package metadata requires Python 3.12 or later. Additional scanners/tools and target setup may add dependencies. The project describes hosted Cloud and Enterprise services with separate account, billing, and data-flow terms; exact prices were not assessed. LLM API costs depend on provider/model and usage. A shell installer is documented; it was not run.

Codex compatibility is explicit: project documentation lists Codex among SKILL.md-compatible coding agents and provides `npx skills add usestrix/strix`. Codex compatibility is through installable SKILL.md instructions that invoke Strix CLI/cloud workflows; Strix is not a native Codex plugin or MCP server. Separately, Strix can act as an MCP client by connecting to configured local/remote MCP servers. No first-party MCP server supplied by this resource was established.

## Security, privacy, and license

Strix performs active reconnaissance and testing, and may create requests, modify test state, execute commands in a sandbox, and generate proof-of-concept artifacts. Sandbox isolation reduces some host exposure but was not validated; configured MCP tools, network access, LLM APIs, cloud features, credentials, source code, and captured target data expand the trust boundary. Reports may contain secrets, vulnerability details, or personal data and require protected storage and retention controls. Only authorized targets and written scope are appropriate.

The repository declares Apache-2.0. External scanner, model, cloud, and integration terms are separate. No claim of accuracy, safety, or security certification is made.
