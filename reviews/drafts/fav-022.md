## Why it matters

OpenCut is a video-editing project whose current repository says it is being rewritten from the ground up. The maintainers list future plans for web, desktop and mobile apps, an editor API, plugins, an MCP server, headless rendering and scripting. The README explicitly says the prior `opencut-classic` repository is the version to use today, while the rewrite is not ready to replace it. Therefore, “open-source CapCut alternative” is the maintainer's project description, not evidence that the current rewrite provides equivalent editing features. [R1]

Potential professional use would depend on the mature classic version or future completion of the rewrite. Possible activities include assembling video timelines, media organization and creative production, for sectors such as marketing, education and media. ## Architecture and capabilities

The repository currently presents a monorepo with `apps/`, Rust workspace files, a browser application and desktop application scaffolding. The root instructions use the `proto` toolchain and Moon task runner to start web, API and desktop development processes. The inspected web package contains Vite, React, TypeScript-related packages, tests and deployment tooling; these manifest entries do not prove the product features are complete. [R1][R2][R3][R4]

The desktop README describes a GPUI-native application and states that the app is “very early” and presently only opens a window. Documented desktop platform prerequisites include Xcode command-line tools on macOS, Vulkan plus Wayland/X11 system packages on Linux, and notes about Windows and WSLg. This describes the developer environment; it does not establish shipped installers or user-facing video editing functionality. [R2]

The current repository page mentions an Editor API, plugin-first design, MCP server, headless mode and scripting as “what's coming.” These features must remain roadmap, not cataloged as implemented. The app's current browser/API privacy, media upload/storage, FFmpeg/codec behavior and export pipeline could not be established from the reviewed top-level documents. No assumption of client-side processing is made. [R1]

## Requirements and integration

**Development requirements.** The README documents `proto` for pinned tools and Moon commands for web, API and desktop development. The web manifest includes Vite, React, TypeScript, Cloudflare tooling and a package-manager allowlist; root files include a Rust workspace and lockfile. A desktop build requires native toolchains and platform libraries described in its README. Requirements for a finished end-user application are not yet established. [R1][R2][R3][R4]

**Operating systems.** Development documentation covers Linux, macOS, Windows and WSL, with platform-specific caveats for Vulkan, Wayland/X11, Xcode and WSLg. This is not proof that the editor ships or functions on all those operating systems. [R1][R2]

**Video features and dependencies.** The current README does not document a complete editing workflow, supported codecs, export settings or tested hardware profiles. FFmpeg usage and media-storage/data flows were not confirmed for the rewrite's current code; no claims about local/browser processing or remote file upload are made. [R1]

**Codex.** The current README lists an MCP server for AI agents as future work. No current Codex plugin, MCP server endpoint or supported integration was verified. Reading source or having Codex invoke a shell command would not constitute native compatibility.

## Security, privacy, and license

The repo's top-level docs are insufficient to determine whether the rewrite stores video locally, uploads media, uses a backend, integrates third-party services or includes telemetry. Assess current runtime behavior, dependency provenance, media processing and data retention before using sensitive footage. In the current desktop app, status documentation indicates an early shell rather than a usable editor. [R1][R2]

The repository lists MIT for its code. That does not grant rights to user media, bundled assets, templates, fonts, third-party dependencies or codec implementations. Codec patent and build-license details depend on the exact libraries and configuration and remain unresolved. [R1]
