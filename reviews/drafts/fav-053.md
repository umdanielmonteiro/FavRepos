## Why it matters

Diagram Design is an agent skill and plugin bundle for producing editorially styled technical and data diagrams. It routes model instructions to type-specific references and templates, supports redraw/import workflows for formats such as draw.io and Mermaid, and documents HTML/SVG outputs. Its intended users include software teams, educators, and technical communicators who need diagrams as deliverables.

The skill uses progressive disclosure: its top-level instructions route the request to a relevant semantic pattern/type reference. The README documents brand tokens, system font options, static diagram variants, editable import/redraw, and optional export. HTML output is described as self-contained in the sense of inline SVG and files/templates, but the README also documents Google Fonts as the default font source. “Self-contained” therefore does not mean that every output is guaranteed to make zero network requests.

Accessibility is addressed in templates via SVG `role="img"`, `aria-labelledby`, `<title>`, and `<desc>` slots. This is a documented design provision, not verification that generated diagrams contain accurate labels or meet accessibility requirements. The sources make no cross-browser pixel-identical rendering guarantee; none is inferred.

## Requirements and integration

- **Skill installation:** README documents `npx skills add cathrynlavery/diagram-design`, with a shared `skills/diagram-design/` directory and references/assets/scripts. It documents additional Agent Skills host options, including OpenCode and Pi. This CLI install is distinct from marketplace/plugin installations.
- **Codex:** A `.codex-plugin` manifest and Codex marketplace metadata are listed, and the project explicitly names Codex. Compatibility is documented only; installation and runtime behavior are untested.
- **Other plugins:** The repository listing includes Claude and Factory plugin directories. Pi installation is separately documented as a Pi package. Plugin manifests do not make the skill an MCP server.
- **Output:** HTML with inline SVG is the primary documented output. Static output is the default; additional modes and imports are documented. “Self-contained” HTML may reference remote fonts unless system fonts are selected.
- **SVG export:** README documents a packaged Python helper. Exact Python/runtime version requirements were not established here.
- **PNG export:** Requires Python Playwright and Chromium installation according to the export documentation. These were not installed.
- **Imports:** README documents redraw/import for draw.io and Mermaid and also references Excalidraw support in current skill metadata; exact format coverage varies by path and was not exercised.
- **External resources:** Default font requests may go to Google Fonts. Optional browser rendering requires installed Playwright/Chromium. The complete dependency graph and all network references were not exhaustively checked.

## Security, privacy, and license

The skill may read project files, brand pages, diagrams, or imported markup and then create HTML/SVG files. Treat untrusted source diagrams, prompts, and imported content as untrusted data. Review generated HTML/SVG before opening in a browser or sharing; inline SVG and embedded content can carry active markup, and this review did not inspect every sanitization path. A repository security policy and self-checks are not proof of safety.

The repository states MIT and includes third-party license notices. Fonts and other bundled or externally loaded assets may carry separate terms. Confirm rights for reused templates, fonts, icons, and imported assets. Default font loading has a privacy/network implication; the documented system-font option can avoid the Google Fonts request. No full content-security or browser isolation audit was performed.
