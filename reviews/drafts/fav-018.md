## Architecture and operations

A workflow consists of connected nodes that can be triggered manually, by schedule, webhook or integration events. The platform can run in a single process or queue mode with a main instance, webhook processors and workers. Queue mode uses Redis to distribute work; PostgreSQL is recommended for scaled deployments. Binary-data storage and filesystem behavior vary by deployment mode; the docs state filesystem binary storage is not supported for queue mode, and some external/S3 storage paths are enterprise features. [R2][R6]

Credentials are stored in the database encrypted using an instance encryption key; all workers need compatible key configuration. The REST API uses API keys. A webhook made publicly reachable can trigger workflows from outside the installation. Workflow nodes may transmit data to external services, while custom or community nodes broaden the code running with the service's privileges. These operational boundaries should be reviewed for each deployment. [R7][R8][R9][R10]

## Security, privacy, and license

The official security guidance highlights credential protection, risky nodes, unprotected webhooks, public access, misconfiguration and the need to keep versions current. The process-level permission model matters: code execution nodes and community packages can have access available to the n8n process, so isolate and constrain the service, review packages, limit network and filesystem permissions, and authenticate/limit webhooks. Encryption at rest protects database values only within the documented key model; key custody and worker configuration remain operator responsibilities. No security audit was conducted for this review. [R7][R9][R10]

The previously viewed mutable-branch license page identifies the Sustainable Use License v1.0; the candidate LICENSE file was not retrieved. Its grant allows internal business use or noncommercial/personal use under conditions; offering n8n as a product/service or otherwise exceeding the grant requires separate commercial terms. Files marked `.ee.` are governed by the enterprise license, and third-party dependencies/components retain their own licenses. Review the exact license and intended business model before redistribution or hosted service use. [R3][R4]

Workflows can contain personal/customer data, credentials and business logic. Their nodes may transmit data to third-party services. Operators should map data flows, retention, subprocessor terms and access controls per workflow rather than infer privacy from self-hosting alone.
