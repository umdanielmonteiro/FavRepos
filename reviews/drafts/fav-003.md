## Why it matters

yt-dlp is a Python command-line program and importable Python package for extracting media and metadata from supported websites and downloading the selected media. The project is a fork of youtube-dl. It is a CLI utility, not a hosted downloading service, Codex skill, or native Codex plugin. The README links an extractor catalogue covering many sites, while warning that listed sites may be broken as websites change and that listing is not a guarantee of working support. [R1][R4]

Plausible uses include retrieving media a user owns or has permission to copy, archiving public-domain or appropriately licensed material, and research or editorial workflows where terms, rights and source policies permit. These are use-case inferences, not legal advice or proof that any particular download is authorized. The canonical repository URL matches the existing `fav-003` entry; no duplicate canonical URL was found.

## Architecture and capabilities

The project is organized around Python extractors that turn a URL into structured metadata and one or more available formats; downloader backends retrieve the media, and postprocessors can merge streams, convert audio/video, embed subtitles or thumbnails, and perform other transformations. The repository also provides a Python `YoutubeDL` API for embedding the library in another application. Site extraction is maintained against changing third-party websites, so the source catalogue and feature set do not guarantee that a particular site, account, format or URL will work at a later date. [R1][R4][R5][R6]

The CLI supports URL and playlist selection, format filtering and sorting, output templates, metadata and thumbnail writing, manual and automatic subtitle retrieval, proxy configuration, rate limits, retries, resumption, download archives, partial downloads by chapter/time range, and post-processing. `supportedsites.md` explicitly says listed extractors are not guaranteed to work. The project recommends the nightly channel for regular users and acknowledges that even stable may lag site changes. These are capabilities and maintainer statements, not a service-level guarantee. [R1][R9]

Format availability is discovered per extractor and URL rather than a fixed universal set. Users can list available formats and select video-only/audio-only streams or combined formats. When separate streams need merging, the documented merged containers are AVI, FLV, MKV, MOV, MP4 and WebM; codec availability depends on the source streams, and FFmpeg may be required. Audio extraction advertises AAC, ALAC, FLAC, M4A, MP3, Opus, Vorbis and WAV options. Subtitle selection supports language and format preferences, including automatic captions when the site exposes them. None of these outcomes were exercised. [R1][R6]

## Requirements, installation and updates

**Python installation.** `pyproject.toml` declares Python `>=3.10`, no mandatory Python runtime dependencies, and optional extras. The documented supported matrix is CPython 3.10+ and PyPy 3.11+. The `default` extra includes networking and media metadata packages such as `requests`, `urllib3`, `websockets`, `certifi`, Brotli, Mutagen, PyCryptodome and `yt-dlp-ejs`. Other extras include `curl-cffi`, `secretstorage` and `deno`. Exact transitive dependencies vary by extra, interpreter and platform. [R1][R4]

**Standalone distributions.** The project publishes a Windows x64 executable (Windows 8+), macOS universal executable (macOS 10.15+), Linux glibc and musl variants, and several ARM/x86 variants. The platform-independent Unix zipimport executable needs Python. The README supplies SHA-256/SHA-512 checksum files and signatures for release assets. These are documented packaging targets, not platform test results. [R1]

**FFmpeg.** The `ffmpeg` and `ffprobe` executables (not the similarly named Python package) are strongly recommended and needed for stream merging and many post-processing tasks. The project links to its own FFmpeg builds but notes the FFmpeg license depends on the selected build. [R1][R6]

**JavaScript for YouTube.** The README says `yt-dlp-ejs` plus a supported JavaScript runtime/engine is needed for full YouTube support, listing Deno, Node.js, Bun and QuickJS and recommending Deno. The `default` Python extra pins `yt-dlp-ejs` to a version; additional runtime acquisition and compatibility remain separate requirements. [R1][R4]

**Network and accounts.** Normal extraction/download needs outbound access to the target site and its media hosts; self-update checks need GitHub access. There is no general yt-dlp API key or yt-dlp-hosted service requirement documented for basic operation. Individual extractors may require an account, credentials, cookies, proxy, or site-specific access. Such requirements and costs belong to the target service and network plan; no cost is inferred here. [R1][R5][R7]

**Updating.** Release binaries support `-U` for their current channel and `--update-to` for channel/tag changes; the README describes stable, nightly and master channels and warns that master can regress. Package-manager installs should be updated through the same package manager. The updater fetches a `SHA2-256SUMS` release asset and checks the selected binary hash when that asset includes the binary; if the asset is missing (404), it warns that verification is skipped. The README also warns that binaries from a user-selected, different repository are not verified by yt-dlp. Prefer official sources and independently verify release signatures/checksums. [R1][R7]

## Authentication and privacy

The CLI supports username/password, two-factor prompts, `.netrc` files/commands, video passwords, and importing a cookie jar in Netscape format. It can also read cookies from Chromium-based browsers, Firefox and Safari profiles, with platform keyring support documented for Chromium decryption. Browser-cookie extraction reads local browser databases and decrypts session material; this can expose logged-in account access if cookie files, logs, backups or downloaded outputs are shared. A cookie jar may also be written back when cookie-file mode is used. Keep it private, restrict filesystem access, and revoke sessions if exposed. This is a risk analysis from the implemented data paths, not a finding of a vulnerability. [R1][R5]

The program downloads media and metadata to user-selected paths and supports caches and diagnostic outputs. Options such as `--write-pages`, `--dump-pages`, verbose/network tracing, and info JSON can preserve intermediary pages or metadata locally; these may contain private URLs, account identifiers or other sensitive context. The README says `file://` URL access is disabled by default for security reasons, but also exposes options to disable certificate checks or allow insecure retrieval. These are explicit trust-boundary choices and should be treated as high risk on untrusted input or networks. No telemetry, data-retention or privacy audit of every extractor was performed. [R1][R4][R5]

Plugins add extractor and postprocessor classes from plugin directories; loading a third-party plugin is code execution in the caller's process and therefore should be limited to reviewed sources. The default installation does not imply that arbitrary plugins are safe. The repository `CONTRIBUTING.md` states that AI/LLM use is prohibited for contributions to the yt-dlp project; this FavRepos assessment is an external catalog review, not an upstream contribution, issue, PR or comment. No `SECURITY.md` file was present at the reviewed commit; this does not establish that the project lacks private disclosure channels. [R1][R5][R10]

## Security, license and legal considerations

The CLI/package repository is licensed under the Unlicense. The README distinguishes this from release artifacts: PyInstaller-bundled executables include GPLv3-or-later code and are distributed under GPLv3-or-later; the zipimport Unix executable and source tarball include ISC- and MIT-licensed components; source/PyPI distributions contain code under the Unlicense. Review the license file and bundled third-party notices for the exact distribution selected. FFmpeg builds have separate licensing. This is a summary of project licensing statements, not legal advice. [R1][R8]

Technical capability and legal permission are separate questions. yt-dlp can retrieve media from sites, but that does not grant permission to download or reuse the media, bypass access restrictions, or violate site terms. YouTube's Terms of Service restrict downloading/automated access except where specifically permitted by the service, with prior written permission where applicable, or as allowed by law; its help pages direct users to official flows for downloading their own uploaded videos and say the standard YouTube license is the default. Copyright exceptions, rights-holder permissions, platform terms and local laws may vary by content and jurisdiction. Check the relevant terms and rights before use; this review does not determine legality for any particular download. [R11][R12][R13]
